# One Piece from punk-records instead of TCGCSV

## Why

The catalog wants sources with a clear provenance and, where possible, an open licence. One Piece came from TCGCSV
(TCGplayer data, no licence) matched by name, and the result is poor: on 2026-11-21 only 2,879 of 12,943 Cardmarket
singles (22%) got a card, and most expansions ended up as `cmxNNNN` stand-ins.

[punk-records](https://github.com/buhbbl/punk-records) is a static JSON dataset generated by vegapull from the official
Bandai card list (pipeline code AGPL-3.0; the data is © Bandai/Shueisha, like LorcanaJSON is Ravensburger's). Every
Cardmarket One Piece single prints its card code in the name ("Enel (OP05-098)"), and punk-records is keyed by that code,
so the join is exact on the code. Measured on 2026-11-21 against the English data:

- 98.3% of the Cardmarket codes are in punk-records (missing: the 51 `P-xxx` promos), 94.3% of the singles;
- 134 of the 151 Cardmarket expansions map to a punk-records pack by a clear vote;
- 6,076 singles (47%) get an image without ambiguity, 10,990 (85%) a rarity.

## Goals

- One Piece takes set code, number, rarity and image from punk-records; TCGCSV is no longer used for it.
- Every rule prefers no data over doubtful data (the matcher's principle): a wrong image is worse than none.

## Non-goals

- Yu-Gi-Oh! and Riftbound stay on TCGCSV.
- Japanese: punk-records' `japanese` folder is empty today; only `english` is read.
- DON!! cards (607 singles, no code in the name) stay without enrichment.
- No change to the output format v1.

## Approaches

1. **punk-records joined on the printed code, with a pack vote per expansion (chosen).** Exact on the code; images only
   where the variant is unambiguous.
2. Keep TCGCSV and improve the name matcher: still no licence, still a guess.
3. punk-records for rarity and number only, no images: simplest, but drops images that are certain.

## Design

New module `cardledger_database/sources/punkrecords.py`; `Game("onepiece", 18, ..., True, "punkrecords")` without a
TCGCSV category; `cli._enrichment` dispatches to it. Unlike the other id-keyed sources it needs the Cardmarket products,
so it is called as `punkrecords.fetch(client, products, singles)`.

Download (raw GitHub, branch `main`): `english/packs.json` and `english/index/cards_by_id.json`. Any HTTP or shape error
is a `SourceError`, like the other sources.

Variants: punk-records keys are `<code>` and `<code>_pN` (parallels/reprints); each has its own `pack_id`, `rarity` and
`img_url`. Group them by base code.

1. **Expansion → pack.** For every Cardmarket expansion, each of its singles whose code is in punk-records votes for the
   packs its code's variants belong to. The expansion maps to the top pack when that pack has at least 80% of the
   expansion's coded singles and strictly more votes than the second. (Several Cardmarket expansions may map to the same
   pack.) Mapped expansions go in `Enrichment.expansions`.
2. **Card with image.** A single gets a full `SourceCard` (set code of the pack, number = the code, rarity, image) when its
   expansion is mapped, it is the only Cardmarket product with that code in its expansion, and exactly one variant of the
   code is in that pack.
3. **Card without image.** Otherwise, when every variant of the code has the same rarity, the single gets a `SourceCard`
   with set code (the mapped pack, else the pack of the base code), number and rarity, and empty image URLs.
4. Otherwise nothing: `assemble` already falls back to the expansion's main set and the code in the name.

Sets: one `SourceSet` per pack. Code: the pack label lower case without the dash (`OP-05` → `op05`, `ST-01` → `st01`,
`PRB-01` → `prb01`, `OP14-EB04` → `op14-eb04`); packs without a label use `pk<pack id>`. Name: `title_parts.title`,
else `raw_title`. `released_at`: None (punk-records has no dates).

Rarity: mapped to the short codes the catalog already ships for One Piece (TCGplayer's): Common C, Uncommon UC, Rare R,
SuperRare SR, SecretRare SEC, Leader L, Special SP, TreasureRare TR, Promo P; unknown values pass through unchanged.

Images: punk-records gives one size; `image_url` and `image_large_url` both get the absolute `img_url` (it points to
`en.onepiece-cardgame.com`).

## Verification

- Unit tests for the vote, the three card cases and the set codes, with small fixtures (like `test_lorcanajson.py`).
- A real `generate --game onepiece` into a scratch folder: compare products, enriched, expansions and `with_image` with
  the TCGCSV run (enriched 2,879, expansions 153, with_image 20.9%).
- Spot-check about twenty random singles with an image against Cardmarket (right artwork and rarity).
